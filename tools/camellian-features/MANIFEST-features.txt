WHAT WAS ACTUALLY RESTORED
  1. Early-boot preinit runner. The kernel Makefile disables it when
     $(objtree)/usr/include/linux/unistd.h is absent; `make headers_install`
     created the UAPI headers. Four 4.14 compatibility fixes in nolibc
     (clone3, linux/mount.h, ksys_close, __kernel_timespec) made it build.
     Evidence: runner.elf 15160 bytes; ksu_preinit_runner_start..end in
     vmlinux differ by exactly 15160 bytes; ksu_preinit_init is linked.
  2. CPU identity spoof, partial but real. Writes cpu_data[].reg_midr,
     loops_per_jiffy and elf_hwcap. All three symbols exist in vmlinux
     (see logs/key-symbols.txt), so the io handler does not degrade to
     -ENXIO. The vDSO clock and 64-bit hwcap2 rewrites are NOT implemented:
     Linux 4.14 has no such mechanism. Fake "supported" is refused.

WHAT WAS NOT RESTORED, AND WHY
  3. KPM: the switch and the whole ioctl/forwarding framework are compiled
     in (ksu_extension_kpm_io, do_kpm, sukisu_kpm_bridge are in vmlinux),
     but the bridge only works if a KernelPatch hook is present. It probes
     __arm64_sys_truncate / .cfi_jt / .cfi; Linux 4.14 exposes only the old
     name sys_truncate (see logs/key-symbols.txt). The probe therefore always
     returns -EOPNOTSUPP. This is structural: enabling CONFIG_KPM does NOT
     make KPM usable on this kernel. It would need a KernelPatch port plus
     actual .kpm module files, neither prepared nor tested here.
  4. SuSFS: CONFIG_KSU_SUSFS=y fails with 'linux/susfs.h file not found'.
     The upstream build itself prints "You have not integrated susfs in your
     kernel yet". SuSFS is an out-of-tree kernel patch, not a config switch.
     Left disabled rather than faked.
  5. CPU spoof vDSO/hwcap2 and KSU_IOCTL_SET_SPOOF_VERSION (present in the
     official release userspace, absent from the builtin UAPI) remain known
     gaps from before this round.
