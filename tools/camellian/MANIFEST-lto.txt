CORRECTED ROOT CAUSE
  The shipped defconfigs DO contain CONFIG_LTO_CLANG=y and CONFIG_CFI_CLANG=y.
  The earlier claim that "the defconfig omitted the parent switches" was wrong.
  The options were removed by the kernel Makefile's check-clang-specific-options
  target during the very first build attempt, which used gcc because CC=clang was
  only exported as an environment variable. That target silently deletes clang-only
  options and runs olddefconfig. Later builds used clang but never restored them.
