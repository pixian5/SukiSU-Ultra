## 一、为什么要做这件事

这份检出原本直接指向上游项目 `SukiSU-Ultra/SukiSU-Ultra`，而当前 GitHub 账号 `pixian5` 对上游**没有写权限**。2026-11-06 20:12 写完项目分析报告后尝试推送，被远程返回 403 拒绝。为了让本地提交能正常保存到一个有写权限的远程，在 GitHub 上创建了自己的分叉，并把推送目标切到分叉。

## 二、现在的关系

| 角色 | 地址 | 权限 | 用途 |
| --- | --- | --- | --- |
| 自己的分叉（本地远程名 `origin`） | `https://github.com/pixian5/SukiSU-Ultra` | 可读写 | 日常提交、推送、保存自己的分支 |
| 原始上游（本地远程名 `upstream`） | `https://github.com/SukiSU-Ultra/SukiSU-Ultra.git` | 只读 | 拉取上游新提交、跟进官方更新 |
| 本地 `main` 分支 | —— | —— | 跟踪自己的分叉 `origin/main` |

分叉由命令行工具 `gh repo fork` 创建，GitHub 记录的父仓库确认是 `SukiSU-Ultra/SukiSU-Ultra`，默认分支为 `main`，账号具备推送权限。分叉创建时把上游当时已有的分支一并带了过来：`main`、`dev`、`old`、`builtin`、`builtin-new`、`chore/icon-license`、`feat/builtin-nyazygisk`、`feat/manager-status-card-splash`、`fix/ksuinit-vermagic-release-guard`、`weblate-sukisu-ultra-manager`。

**注意**：命令行工具的 fork 子命令虽然返回了分叉地址，但**没有自动在本地添加远程**；上面的两个远程是随后手动配置的。

## 四、以后怎么用

```sh
# 日常提交：直接推，会推到自己的分叉
git add <文件>
git commit -m "说明"
git push

# 看上游比自己的分叉多出哪些提交
git fetch upstream
git log --oneline origin/main..upstream/main

# 把上游更新合进来，再推回分叉
git merge upstream/main
git push

# 核对本地、分叉、上游三者的位置
git log --oneline --decorate -5
git branch -vv
```

**不要**直接 `git push upstream main`：账号对上游没有写权限，会被 403 拒绝。如果要给上游贡献代码，正确做法是先推到自己的分叉，再从网页发起合并请求。

## 五、术语说明

- **分叉（fork）**：在 GitHub 上把别人的仓库复制一份到自己账号下，自己这份可以随意改，原仓库不受影响。
- **远程（remote）**：本地仓库里记录的远程仓库地址别名，`origin` 和 `upstream` 都只是名字。
- **跟踪分支**：本地分支记住自己对应哪个远程分支，之后不带参数的 `git push` / `git pull` 才知道该往哪推、从哪拉。
- **合并请求（pull request）**：请求对方把自己的改动合进原仓库的流程。
