```bash
payload-dumper-go_2.1.0_linux_amd64.tar.gz
sha256 bbbb53a71955c69272afdef7bc7e83a1bb1770f453d0c21dcaf61a3ba0463c11（与官方校验文件一致）

payload-dumper-go -p boot,vbmeta,vbmeta_system,vbmeta_vendor,dtbo \
  -o extract miui_CAMELLIANGlobal_V14.0.6.0.TKSMIXM_8be0f8ee2d_13.0.zip
```

## 4. 和当前系统那份的对照（关键）

| 项 | V14.0.4.0 EEA（手机当前 b 槽 / 云电脑线刷包） | V14.0.6.0 Global（本次提取） |
| --- | --- | --- |
| 内核版本串 | `4.14.186-perf-gf8d872e9279c` | `4.14.186-perf-gf8d872e9279c`（**相同**） |
| 构建者标识 | `…-153136-0x4dm-br798-xxm7r` | `…-154817-ht6k7-lt7lp-7fqnc`（**不同**） |
| 编译时间 | Thu Sep 14 12:02:46 UTC 2023 | Tue Sep 19 12:46:50 UTC 2023（**晚 5 天**） |
| 内核字节数 | 13,342,418 | 13,340,883（**差 1,535**） |
| 内存盘字节数 | 21,078,370 | 21,078,382（**差 12**） |
| 文件 MD5 | `f8e4f42a4538b03c519bb70921d88bcc` | `c57babde9258e16aa699409c5d9f0322` |

**结论**：两份用的是同一个内核源码基线（所以版本串相同），但**不是同一次构建**，二进制不同，不能互相替代。MIUI 这种「内核版本串不变、重新编译打包」的情况很常见，因此：

- 判断两份镜像是否同一份，**必须**比完整的版本行（含构建者标识与编译时间）和校验值；
- 只看内核版本串会误判；
- 只看文件名或内存盘大小同样会误判（这次内存盘只差 12 字节）。

另外，这两份的区域分支也不同：当前系统与云电脑线刷包是 **EEA（`TKSEUXM`）**，这次下载的包是 **Global（`TKSMIXM`）**。系统版本号从 `V14.0.4.0` 前进到了 `V14.0.6.0`。

## 5. 这份 boot.img 能拿来做什么、不能做什么

**能**：作为 `V14.0.6.0 Global` 这一代的原厂启动镜像参照；如果将来完整升级到该版本，它是那一版对应的原厂启动分区素材之一。

**不能**：**不是当前手机系统（`V14.0.4.0 EEA`）的同版本原厂镜像**，不能替代云电脑线刷包里那份 `V14.0.4.0` 的同代原厂回退件，也不能单独刷进当前槽当作「回退到原厂」。只刷启动分区而系统分区仍是旧版本，属于跨版本混搭；跨区域分支（Global / EEA）也会带来版本与区域不一致的问题。真正的升级应当走完整整包流程，而不是只换一个分区。
