# 原版内核试编成功与工具链适配

- 生成时间：2026-11-06 22:01
- 关联文档：[云电脑编译环境体检与量产配置来源结论](./20261106-2132-云电脑编译环境体检与量产配置来源结论-Claude-Opus-6.md)

## 0. 结论速览

**原版内核编出来了。** 在云电脑上，用小米官方开源源码 + 谷歌官方那套编译器，成功产出内核镜像 `Image.gz-dtb`（12 MB），`make` 返回码 0。这回答了上一轮留下的唯一未知数：这套环境确实能把这台手机的 4.14 内核编出来，工具链障碍已经清除。

跑通它一共处理了 5 处「小米开源包不自洽」造成的障碍，其中 3 处是配置缺项、1 处是缺失的厂商生成文件、1 处是构建参数写法。**没有任何一处改动了现有的内核源码逻辑，也没有集成 SukiSU-Ultra。**

同时**更正了上一份文档里一个错误判断**：此前根据配置文件里的两行内容推断「这份内核只能用 clang 编译」，实测证明那两行在配置展开时被内核自身的依赖逻辑清掉了，并不生效。详见第 4 节。

## 1. 这一轮的边界

**做了**：在云电脑上安装编译工具、重新检出官方内核源码、生成配置、试编一次未集成任何 root 方案的原版内核、核验产物、清理临时文件。

## 3. 环境与工具链准备

云电脑：Ubuntu 24.04.5、Linux x86_64、4 核、7.7 GiB 内存、40 GiB 磁盘（编译前有 39 GiB 可用）。

**软件源安装的编译依赖**（`sudo apt-get install -y`）：

```text
clang-14 lld-14 llvm-14 gcc-aarch64-linux-gnu device-tree-compiler
bison flex bc libssl-dev libelf-dev ccache libncurses-dev kmod cpio xz-utils python3
```

**官方编译器**：`clang-r383902` 不是 Git 分支名，而是谷歌安卓源码树 `platform/prebuilts/clang/host/linux-x86` 仓库在 `android11-release` 分支下的一个子目录。用 Gitiles 的打包接口只下这个目录：

```sh
curl -L -o /workspace/clang-r383902.tar.gz \
  'https://android.googlesource.com/platform/prebuilts/clang/host/linux-x86/+archive/refs/heads/android11-release/clang-r383902.tar.gz'
mkdir -p /workspace/aosp/clang-r383902
tar xzf /workspace/clang-r383902.tar.gz -C /workspace/aosp/clang-r383902
```

包 327 MB，解压后 1.1 GB，内含 `clang`、`clang-11`、`ld.lld`、`llvm-nm`、`llvm-objcopy`、`llvm-ar`、`LLVMgold.so` 等 47 个工具。版本实测：

```text
Android (6443078 based on r383902) clang version 11.0.1
```

**源码**：`git clone --depth 1 --single-branch -b camellian-t-oss` 到 `/workspace/camellian-kernel`，1.4 GB / 78342 个文件。

**最终构建脚本** `/workspace/build.sh`（保留在云电脑上，可直接复跑）：

```bash
#!/bin/bash
cd /workspace/camellian-kernel || exit 99
export PATH=/workspace/aosp/clang-r383902/bin:$PATH
export LD_LIBRARY_PATH=/workspace/aosp/clang-r383902/lib64:${LD_LIBRARY_PATH:-}
make O=/workspace/out -j4 \
  ARCH=arm64 CC=clang CLANG_TRIPLE=aarch64-linux-gnu- CROSS_COMPILE=aarch64-linux-gnu- \
  LD=ld.lld NM=llvm-nm OBJCOPY=llvm-objcopy > /workspace/build.log 2>&1
echo $? > /workspace/build.rc
```

配置生成命令（一次性）：

```sh
make O=/workspace/out ARCH=arm64 CC=clang \
  CLANG_TRIPLE=aarch64-linux-gnu- CROSS_COMPILE=aarch64-linux-gnu- \
  LD=ld.lld NM=llvm-nm OBJCOPY=llvm-objcopy camellian_defconfig
```

生成 5582 行配置，`CONFIG_ARM64=y`、`CONFIG_LOCALVERSION="-perf"`、`CONFIG_KPROBES=y`、`CONFIG_KALLSYMS_ALL=y`、`CONFIG_IKCONFIG_PROC=y` 都在。

## 4. 完整错误链，以及为跑通做的 5 处适配

编译不是一次通过的。下面按实际发生顺序记录，**这 5 处就是「官方开源快照无法原样直接编译」的全部证据**。

### 适配 1：编译器参数必须写在 make 命令行，不能写成环境变量

第一次启动编译立刻失败，日志第一行出现：

```text
WARNING: Disabling clang-specific options with gcc
```

原因：内核 Makefile 内部给 `CC` 变量赋了值，环境变量会被它覆盖，结果实际用的是 `aarch64-linux-gnu-gcc`，clang 专属选项被自动关掉。**把 `CC=clang` 等参数从 `export` 改成写在 `make` 命令行上**后解决（即第 3 节脚本的写法）。这是构建参数写法问题，不涉及源码。

### 适配 2：关掉 `CONFIG_MILLET`（开源快照缺私有模块目录）

报错：

```text
scripts/Makefile.modbuiltin:26: .../vendor/xiaomi/kernel_modules/mihw/millet/Makefile: No such file or directory
```

`drivers/mihw/Makefile` 只有一行，指向 `vendor/xiaomi/.../millet/`，而整个 `vendor/` 目录在开源快照里根本不存在。这是小米的「冻结框架」私有模块，源码未随开源包发布。

处理：把配置里 `CONFIG_MILLET=y` 改为 `# CONFIG_MILLET is not set`。`CONFIG_MIHW=y` 保留。

### 适配 3：补一个空的设备树占位文件

报错：

```text
arch/arm64/boot/dts/mediatek/camellian.dts:490:10: fatal error: 'camellian/cust.dtsi' file not found
```

这个文件是小米内部构建时按硬件版本生成的板级配置，开源快照里没有；设备树其余被包含的 `cust_camellian_camera.dtsi`、`cust_camellian_fingerprint.dtsi` 等都在，唯独缺它。

处理：**新增一个只含一行注释的空占位文件** `arch/arm64/boot/dts/camellian/cust.dtsi`，不修改任何现有文件。补上后设备树成功编译（只有若干 `avoid_default_addr_size` 警告）。这也是整个源码树里唯一的新增内容，`git status` 只显示这一个未跟踪目录。

### 适配 4：放宽栈帧告警阈值

报错：

```text
drivers/input/touchscreen/mediatek/FT8722/focaltech_test/focaltech_test.c:2807:16:
error: stack frame size of 4176 bytes in function 'fts_tp_selftest_read'
[-Werror,-Wframe-larger-than=]
```

配置里 `CONFIG_FRAME_WARN=3600`，而编译器算出的栈帧是 4176，被 `-Werror` 升级成错误。这是告警阈值问题，不是代码缺陷。

处理：把 `CONFIG_FRAME_WARN` 改成 `0`（关闭该告警）。因为配置变化会触发全量重编，这一步耗时最长。

### 适配 5：打开 `CONFIG_HQ_SYSFS_SUPPORT`（源码里本来就有实现）

这一次编译推进到最终链接，3126 个 C 目标文件全部编完、设备树也生成了，卡在链接器：

```text
ld.lld: error: undefined symbol: hq_regiser_hw_info
ld.lld: error: undefined symbol: get_huaqin_pcba_config
ld.lld: error: undefined symbol: get_audio_pa_vendor
```

调用方是触摸屏、指纹、音频功放、充电器等多个驱动。追查后发现，这三个函数的**实现就在源码里**（`drivers/misc/hqsysfs/hqsysfs.c` 和 `hqsys_pcba.c`），只是对应 Makefile 用 `obj-$(CONFIG_HQ_SYSFS_SUPPORT)` 控制，而官方配置里这一项是 `not set`。也就是说：量产构建时小米内部脚本会额外打开它，开源配置漏了，导致链接断链。

处理：把 `# CONFIG_HQ_SYSFS_SUPPORT is not set` 改为 `CONFIG_HQ_SYSFS_SUPPORT=y`。该配置项没有额外依赖（`default n` 的普通布尔项），改完能稳定保留。**打开后增量编译 13 个文件即链接成功，`make` 返回 0。**

### 更正：上一份文档「只能用 clang 编」的判断是错的

上一份文档根据 `camellian_defconfig` 里的 `CONFIG_LTO_CLANG=y`（链接时优化，clang 专属）和 `CONFIG_CFI_CLANG=y`（控制流完整性检查，clang 专属）推断「源码里那份纯 GCC 构建配置编不了它，必须准备 clang」。

实测结果推翻了这个推断：

- `make camellian_defconfig` 刚生成配置时，确实能看到这两行。
- 但后续每次 `make` 跑配置再展开时，内核的配置依赖逻辑会重新求值，把它们清掉。最终生效的是：

```text
# CONFIG_LTO is not set
CONFIG_ARCH_SUPPORTS_LTO_CLANG=y
CONFIG_ARCH_SUPPORTS_THINLTO=y
CONFIG_LTO_NONE=y
# CONFIG_LTO_CLANG is not set
```

- 也就是说，那两行是小米配置文件里的历史残留、并不会真正生效，**不能据此推断编译器约束**。本次依然用官方 clang 编通了，但「非 clang 不可」这个理由不成立；纯 GCC 路线是否可行尚未验证，不应再断言「走不通」。

教训记在这里：配置文件里写了某个 `CONFIG_XXX=y`，不等于最终 `.config` 里它就生效；判断实际编译行为必须看构建展开后的 `.config`。

## 5. 产物核验

编译返回码 `build.rc = 0`。产物都在云电脑 `/workspace/out/`：

| 文件 | 大小 | 说明 |
| --- | --- | --- |
| `vmlinux` | 284 MB | 未压缩的内核可执行文件 |
| `arch/arm64/boot/Image` | 32 MB | 可启动的原始内核镜像 |
| `arch/arm64/boot/Image.gz` | 11 MB | 压缩后的内核镜像 |
| `arch/arm64/boot/Image.gz-dtb` | 12 MB | **压缩内核 + 尾部追加设备树**，本机型的最终格式 |

核验细节：

- `vmlinux` 的 ELF 头：`ELF64`、`Machine: AArch64`、入口地址 `0xffffff8008080000`，是真内核不是空壳。
- 内核版本串：

```text
4.14.186-perf-gf4e416aea
Linux version 4.14.186-perf-gf4e416aea (user@main)
(Android (6443078 based on r383902) clang version 11.0.1 ..., LLD 11.0.1 ...) #2 SMP PREEMPT
```

版本串里 `-perf` 与机型配置一致，`gf4e416aea` 与源码提交一致，编译器与链接器都是官方那套。

- `Image.gz-dtb` 总 11,573,496 字节；gzip 负载解压后 32,954,368 字节，与单独 `Image.gz` 解压结果完全一致；末尾偏移 11,441,710 处找到设备树魔数 `0xd00dfeed`，设备树头部声明大小 131,786 字节，与实际剩余字节数一致。格式正确。

- 校验值（MD5）：

```text
a31bc208dc788336714202f78bed1174  Image.gz-dtb
9424a4c8faa8f7aea661e50077f77441  Image.gz
7c1f03f2f8c46c8862c5187f2b1b1c50  vmlinux
```

- 最终保留的关键配置：`CONFIG_KPROBES=y`、`CONFIG_KALLSYMS_ALL=y`、`CONFIG_IKCONFIG_PROC=y`、`CONFIG_MODULES=y`、`CONFIG_LOCALVERSION="-perf"`。前两项在量产内核里是关的，在自编译内核里是开的（这正是上一份文档已经定论的差异）。

## 6. 这个产物能做什么、不能做什么

**能证明的**：云电脑这套环境、这套官方源码、这套官方编译器，可以稳定产出这台手机对应架构的完整内核镜像。以后集成 SukiSU-Ultra 时，不必再担心「工具链装不上」「源码大小写冲突」「编到一半编不动」这类基础问题。

**不能做的（重要）**：

1. **绝对不能刷进手机。** 设备树里厂商私有板级配置是空占位、私有模块 `MILLET` 被关掉、配置与量产内核不同，刷入极可能变砖。
2. 它还没有集成任何 root 方案，也还没有原厂的启动内存盘（ramdisk），**不能直接打包成手机能用的启动分区镜像**。
3. 它只是一次「能不能编」的可行性验证，不是可交付固件。

## 7. 可复跑清单

在云电脑上，环境已保留，重编只需：

```sh
cd /workspace/camellian-kernel
# 配置已保存在 /workspace/out/.config，无需重新生成
/workspace/build.sh
cat /workspace/build.rc        # 期望 0
ls -lh /workspace/out/arch/arm64/boot/Image.gz-dtb
```

从零重建时需要按第 3 节准备工具链和源码，并按第 4 节应用 3 处配置改动 + 1 个占位文件 + 1 处参数写法：

```sh
# 三处配置改动（在 /workspace/out/.config 上）
sed -i 's/^CONFIG_MILLET=y/# CONFIG_MILLET is not set/'                       /workspace/out/.config
sed -i 's/^CONFIG_FRAME_WARN=3600/CONFIG_FRAME_WARN=0/'                      /workspace/out/.config
sed -i 's/^# CONFIG_HQ_SYSFS_SUPPORT is not set/CONFIG_HQ_SYSFS_SUPPORT=y/' /workspace/out/.config

# 一个占位文件
mkdir -p /workspace/camellian-kernel/arch/arm64/boot/dts/camellian
printf '/* Placeholder for vendor-generated board config. Absent from the open-source snapshot. */\n' \
  > /workspace/camellian-kernel/arch/arm64/boot/dts/camellian/cust.dtsi
```

## 9. 下一步需要拍板的事

工具链障碍已经清掉，现在真正剩下的工作才开始。当前状态：手机仍是原有 Magisk Alpha，云电脑上有一份能编通的原版内核源码和完整构建环境，但还没有集成 SukiSU-Ultra，也没有原厂启动分区镜像基线。

需要用户决定的三个方向：

- **A：继续在云电脑上做集成试编。** 把 SukiSU-Ultra 的 `builtin` 分支（给 5.10 以下内核用的手动挂钩版本）接入这份源码，改那 4 个内核文件并配置好，再编一次带 root 方案的内核，验证能否编通。仍然只在云电脑上，不碰手机。代价：要处理 4.14 上函数签名与条件编译的差异，可能还有几轮报错。
- **B：先补原厂启动分区镜像基线。** 从第三方镜像拿 5.4 GB 固件包、校验、解出原厂 `boot.img`，或者（需要用户明确授权动手机）直接从这台已 root 的手机导出当前启动分区。这是将来真要打包可刷镜像时的必要材料。
- **C：先做方案对照。** 把「换成 SukiSU-Ultra 相对现有 Magisk Alpha 的得失、风险、回退办法」整理成文档，再决定要不要投入集成。

推荐 A：既然环境已验证可用、源码已在云电脑上、编译器已就位，集成试编是边际成本最低的一步，且结果无论成败都能直接回答「这台手机到底能不能用 SukiSU-Ultra」。B 可以并行或稍后做，C 随时可做。
