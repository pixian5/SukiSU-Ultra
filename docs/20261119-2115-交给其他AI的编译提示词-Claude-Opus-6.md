# 交给其他 AI 的编译提示词（自包含版）

- 时间：2026-11-19 21:15（GMT+8）
- 用途：让别的 AI 在自己的容器里编出「SukiSU + SuSFS + 授权空包名修复」的可刷启动镜像
- 边界：只编译打包，不刷机、不连手机；产物用独立文件名，不覆盖已有发布

---

## 提示词（可直接复制）

```
你在你自己的 Linux 容器里，帮我编译一颗安卓内核并打包成可刷入的启动镜像。只做编译与打包，不要刷机、不要连接任何手机。

【目标产物】
- 设备：红米 Note 10 5G（代号 camellian / 型号 M2103K19C），Android 13，MIUI EEA V14.0.4.0.TKSEUXM，非 GKI，内核 4.14.186。
- 内容：SukiSU（root 授权）+ SuSFS（隐藏）+ 一处授权修复。
- 输出：boot-sukisu-susfs-allowlist-fix.img（64 MiB），必须通过 12 项结构校验。

【环境要求】
- x86_64 Linux，≥4 核，≥8 GB 内存，≥60 GB 可用磁盘（源码 22 GB + 构建 15 GB + 余量）。
- 依赖：git curl python3 make bc bison flex libssl-dev libelf-dev。
- 工具链：AOSP clang-r383902（clang 11.0.1）
  https://android.googlesource.com/platform/prebuilts/clang/host/linux-x86/+archive/refs/heads/android11-release/clang-r383902.tar.gz
- CC=clang 必须作为 make 变量传入，不能只 export。

【源码与素材（全部公开）】
1. 工具仓库（补丁、脚本、配置都在里面）：
   https://github.com/pixian5/SukiSU-Ultra
   国内镜像：https://gitcode.com/laotongtian/SukiSU-Ultra
   clone 到 /workspace/SukiSU-Ultra
2. 厂商内核：https://github.com/MiCode/Xiaomi_Kernel_OpenSource 分支 camellian-t-oss
3. SukiSU 内核模块：https://github.com/SukiSU-Ultra/SukiSU-Ultra 分支 builtin，commit 1cfa5734
4. 原厂 boot.img（打包要复用它的内存盘、设备树、校验区段）：
   https://github.com/pixian5/SukiSU-Ultra/releases/download/backup-20261108/boot-stock.img
   必须校验 MD5 = f8e4f42a4538b03c519bb70921d88bcc
5. 配置基线：tools/camellian-susfs/config/ikconfig-v0.0.6-mainline.txt

【步骤】
1. 先读 tools/camellian-susfs/README.md 与 docs/20261106-2314-云电脑资产固化与从零复跑手册-Claude-Opus-6.md，以 README 为准。
2. clone 厂商内核到 /workspace/camellian-kernel（camellian-t-oss）。
3. 按 README 应用补丁：
   - tools/camellian-susfs/patches/50_add_susfs_in_kernel-4.14.patch
   - tools/camellian-susfs/patches/10_sukisu-4.14-susfs.patch
   - 必要时用 tools/camellian-susfs/scripts/integrate-susfs.py
   - tools/camellian/patches/kernel-tree.patch
   - tools/camellian/patches/kernel-reboot-ksu-hook.patch
   - tools/camellian/patches/sukisu-dispatch-app-profile-fallback.patch
   - tools/camellian/patches/kernel-lto-mtk-vcu.patch
4. 复制 SuSFS 核心与 ABI 层：
   tools/camellian-susfs/kernel/fs/susfs.c → fs/susfs.c
   tools/camellian-susfs/kernel/fs/susfs_abi.c → fs/susfs_abi.c
   tools/camellian-susfs/kernel/include/linux/susfs.h → include/linux/susfs.h
   tools/camellian-susfs/kernel/include/linux/susfs_def.h → include/linux/susfs_def.h
   确保 fs/Makefile 里 CONFIG_KSU_SUSFS 目标包含 susfs.o susfs_abi.o。
5. 应用授权修复（必须）：kernel/policy/allowlist.c 的 ksu_prune_allowlist() 中，
   在 `bool is_preserved_uid = ...;` 之后插入：
       // 空包名记录无法与已安装应用清单匹配，跳过而不是删除，避免误删有效授权
       if (np->profile.key[0] == '\0') {
           continue;
       }
6. 配置：cp ikconfig-v0.0.6-mainline.txt out/.config，然后 make olddefconfig；
   确认 CONFIG_KSU=y、CONFIG_KSU_SUSFS=y、CONFIG_LTO_CLANG=y、CONFIG_CFI_CLANG=y。
7. 编译（8 核约 30–40 分钟）：
   make O=/workspace/out -j$(nproc) ARCH=arm64 CC=clang \
     CLANG_TRIPLE=aarch64-linux-gnu- CROSS_COMPILE=aarch64-linux-gnu- \
     LD=ld.lld NM=llvm-nm OBJCOPY=llvm-objcopy AR=llvm-ar
   成功标志：返回 0、生成 out/arch/arm64/boot/Image.gz、日志无 error。
8. 打包：改 tools/camellian/scripts/pack_boot.py 顶部 STOCK / KERNEL / OUT_DIR 三个常量指向你的路径，然后
   python3 pack_boot.py /workspace/dist/boot-sukisu-susfs-allowlist-fix.img
   必须 12 项 PASS。
9. 校验并报告：镜像 MD5/SHA256、大小、内核完整版本串、susfs_ 符号数、CONFIG_KSU_SUSFS 实际值。

【必须避免的坑】
- 只 export CC=clang 会让内核静默关掉 LTO/CFI，必须作为 make 变量。
- 缺 bc 会导致 include/generated/timeconst.h 失败，先装 bc。
- drivers/media/platform/mtk-vcu/Makefile 里 mtk_vcodec_mem.o 重复，LTO 下报重复符号，删掉多余条目（补丁已处理）。
- 不要用厂商 flash_all_lock.sh（会重新上锁）。
- 不要覆盖任何已有发布资产；产物用独立文件名。
- 不要刷机、不要连手机、不要发布到主线 Release。

【回报格式】
编译是否成功/耗时、Image.gz 大小、内核完整版本串、susfs_ 符号数、镜像 MD5/SHA256/大小、12 项校验结果、产物下载地址、遇到的错误与解法。
```

## 备注

- 提示词里的路径都以本仓库根目录为基准；别的 AI clone 后直接能看到。
- 原厂 `boot-stock.img` 在公开 Release 里可匿名下载（GitHub），GitCode 的附件需要登录。
- 如果对方的磁盘不足 60 GB，先扩容或换机器；这颗内核的构建产物比较大。
- 产物只用于本项目后续验证，不承诺可直接刷入；刷机前仍需核对校验值与回退件。
