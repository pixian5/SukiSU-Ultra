# 新授权会不会再被清、SuSFS 新内核好不好刷

- 时间：2026-11-19 20:40（GMT+8）
- 设备：Redmi Note 10 5G（M2103K19C / camellia），Android 13，当前内核 `#11`（final3，无 SuSFS）
- 用户问题：「后续还要给其他 APP 授权，现在的修复能否解决？SuSFS 的新内核是否容易刷？」

---

## 一、当前修复只覆盖存量，不覆盖新增

刚才做的修复，是把 **uid 10800（InstallerX）那一条**授权记录的包名从空补成 `com.rosan.installer.x`，并同时更新了内核内存与磁盘文件。

它**不能**覆盖后续新应用的首次授权，原因很直接：

- 管理器打开一个从未授权过的应用时，会向内核要配置；
- 内核对这个 uid 没有记录，返回一份**清零的默认配置**（不带包名）；
- 管理器的 JNI 层先把传入的包名写进结构，但内核返回后整体覆盖，包名变回空；
- 用户打开开关保存，空包名就被写进 `.allowlist`；
- 之后任何一次「装 / 更新 / 卸载应用」触发清理，这条记录就会被删。

所以：**新授权在「不装应用、不重启」期间能用；一旦触发清理就没了。**

---

## 二、要覆盖新授权，必须让代码修复生效

| 路径 | 效果 | 代价 |
| --- | --- | --- |
| 内核修复：清理时跳过空包名 | 新记录即使包名为空也不会被删 | 需要重编内核并刷入 `boot_b` |
| 管理器修复：JNI 补回包名 | 新记录直接写成正确包名 | 需要重编管理器 APK；本机缺 NDK 与签名，暂不可行 |
| 手动补包名 | 只解决当次 | 每授权一个新应用都要手动执行一次 `ksud apply` |

因此选择**重编内核**，正在进行。

## 四、SuSFS 新内核好不好刷

**刷机动作本身很容易**：

```
adb reboot bootloader
fastboot devices
fastboot getvar current-slot     # 应为 b
fastboot flash boot_b <镜像>
fastboot reboot
```

约 2 分钟；只写 `boot_b`，`boot_a`、用户数据、校验分区都不动。

**真正的风险不在刷，而在镜像本身**：

1. SuSFS 这套代码**从未在真机上验证过**，只有编译与结构校验通过；
2. 这次内核还带着实验变体的 `CONFIG_KALLSYMS_ALL=n`（同样未真机验证）；
3. 如果开机异常（大概率不会，但不能排除），需要重新进 fastboot 刷回。

**回退件已就位**：`backup/camellian/boot-sukisu-final3-lto-stockdtb.img`，MD5 `3f687ecbc07f24ac0ecfbea56ebe14f5`，就是当前正在运行的 final3，刷回即可恢复现状。

**建议**：编完后先不急着刷，确认校验值和结构校验都过；刷之前你再确认一次「现在刷」，刷完按判据验证（能开机、管理器工作中、新授权装应用后仍保留）。
