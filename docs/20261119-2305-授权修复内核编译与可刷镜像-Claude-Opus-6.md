   `https://mirrors.ustc.edu.cn/aosp/platform/prebuilts/clang/host/linux-x86.git`
   的 `android11-release` 分支，`--filter=blob:none` + sparse checkout 只取 `clang-r383902`（1.1 GB）
3. 源码：`MiCode/Xiaomi_Kernel_OpenSource` 分支 `camellian-t-oss`（`f4e416aea`）；
   SukiSU 用 `builtin` 分支
4. 内核侧补丁：`kernel-tree.patch`、`kernel-reboot-ksu-hook.patch`、`kernel-lto-mtk-vcu.patch`
5. SuSFS 接入：`integrate-susfs.py` 应用 `50_add_susfs_in_kernel-4.14.patch`，
   覆盖 `fs/susfs.c`、`fs/susfs_abi.c`、`include/linux/susfs*.h`
6. SukiSU 侧：`10_sukisu-4.14-susfs.patch`（6/7 hunk 成功）
7. 授权修复：`kernel/policy/allowlist.c` 在 `ksu_prune_allowlist()` 跳过空包名
8. 配置：`config/ikconfig-v0.0.6-mainline.txt` → `make olddefconfig`
9. `make headers_install`（preinit runner 需要 `usr/include/linux/unistd.h`）
10. 全量 `make -j3`，`rc=0`

## 三、本轮新增的四个坑（文档未覆盖）

1. **`fs/open.c` 重复 extern**：`kernel-tree.patch` 已插入 `ksu_handle_faccessat`
   的 extern 与调用点，`integrate-susfs.py` 的锚点匹配不到并再插一份；
   出现重复声明后需要手工去重，脚本才能继续跑到 setresuid 步骤。
2. **`kernel/sys.c` 的 setresuid 钩子**：脚本中途退出会漏掉这一步，需手工补
   `ksu_handle_setresuid()` 调用。
3. **preinit runner 在 4.14 编译失败**（三个错误）：
   - `struct clone_args` 不存在 → 用 `__NR_clone`
   - `<linux/mount.h>` 不存在 → 回退 `<linux/fs.h>`
   - `ksys_close()` 是 4.17+ → 用 `sys_close()`
   仓库内 `tools/camellian-features/patches/sukisu-4.14-optional-features.patch`
   的 preinit 段可直接套用。
4. **`camellia.dts` 同样缺 `cust.dtsi`**：提示词只提到 `camellian.dts`，
   实际编译会同时产出 `camellia.dtb`。两个 dts 都要建目录、复制 `cust.dtsi`
   并把尖括号 include 改成引号。
