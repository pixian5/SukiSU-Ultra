# 红米 Note 10 5G 的 SukiSU-Ultra 兼容性评估

> 调研时间：2026-11-06 20:30（GMT+8）
> 撰写模型：Claude Opus 6
> 依据：本仓库 `docs/README.md`、`docs/guide/installation.md`、`docs/guide/how-to-integrate.md` 原文，加上公开设备资料与厂商开源内核索引的网络检索
> 结论一句话：**不能直接按常规方式使用；理论上可行，但需要自己编译内核，属于开发者级操作。**

---

## 一、先把机器认准

「红米 Note 10 5G」这个中文名对应的是联发科平台那一台，社区代号 `camellia` / `camellian`：

| 项目 | 查到的值 |
| --- | --- |
| 型号 | 国行 `M2103K19C`，国际版 `M2103K19G` |
| 处理器 | 联发科天玑 700（MT6833） |
| 出厂系统 | Android 11 / MIUI 12 |
| **Linux 内核版本** | **4.14.186**（多个设备信息库与 XDA 讨论交叉印证；后续第三方系统移植仍基于 4.14 系，如 4.14.357） |
| 同硬件马甲 | POCO M3 Pro 5G、Redmi Note 10T 5G、国行 Redmi Note 11SE |

**必须先确认型号**：市场上还有「Redmi Note 10（4G 版，代号 sunny/mojito，骁龙 678）」和「Redmi Note 10 Pro 5G（代号 chopin，天玑 1100）」，这三台是不同机器，内核与刷机包完全不通用。在手机「设置 → 关于手机」里看型号字符串，或用一个能读硬件信息的应用看内核版本。

## 二、为什么「常规方式」用不了

本仓库文档把安装方式分成两类，分界线就是内核版本：

| 设备的内核 | 文档给的方式 | 这台机器能否用 |
| --- | --- | --- |
| 5.10 及以上的通用内核规范设备 | 管理器直接修补 boot 镜像、或刷入预编译内核模块、或刷现成的通用内核包 | **不能**，它是 4.14 |
| 4.14 及以上的旧内核 / 非通用内核规范设备 | **自行编译内核**，把 SukiSU 集成进内核源码 | 这是唯一路径 |
| 3.x 内核 | 需要更多反向移植 | 不涉及 |

原文两处关键表述（意译）：

- `docs/README.md`：「旧内核也可兼容（最低 4.14+），但需要自行编译内核。」
- `docs/guide/how-to-integrate.md`：「前提是有一份开源且能开机的内核源码」「厂商定制导致非通用内核规范的内核碎片化严重，没有通用构建方法，**因此无法为这类设备提供 boot 镜像**」。

也就是说：**这个项目不会给你一个能直接刷进这台手机的现成包**。原因不是「不支持 4.14」，而是 4.14 的厂商内核各家都不一样，只能自己从源码编。

另外，在上游仓库的议题里检索 `camellia` / `camellian` / `Note 10 5G`，**结果为零**，说明项目侧没有人为这台机器维护现成适配。

## 三、理论上可行的那条路，具体要做什么

### 3.1 好消息：内核源码确实有

- 小米官方开源索引 `MiCode/Xiaomi_Kernel_OpenSource` 里有 `camellian-t-oss` 分支，标注对应「POCO M3 Pro 5G / Redmi Note 10 5G / Redmi Note 10T」的 Android 13 版本；另有 `camellia-r-oss` 分支，但那台是 4G 版，别拿错。
- 社区还有若干基于 LineageOS 23.2（Android 16）的 `android_kernel_xiaomi_camellia` 源码树，从上述官方源码起步并合并了 4.14.357 稳定补丁，XDA 上有实际开机报告。
- 也搜到过名为「红米Note10 KernelSU内核编译」的社区工程，但**未能确认它针对的是 5G 版还是 4G 版**，用之前必须自己核对代号与型号，不能照抄。

### 3.2 具体步骤（每一步都是硬门槛）

1. **解锁 Bootloader**（开机时校验系统签名的那道锁）。不解锁就刷不进任何改过的内核。
2. **取得并先独立编译出一份能正常开机的内核**——这是项目文档反复强调的前置条件：先证明你会编这个机型的内核，再谈加 root。
3. **把 SukiSU 集成进内核源码**：项目提供 `kernel/setup.sh` 把代码挂进 `drivers/kernelsu`。4.14 的厂商内核通常要用 `builtin` 分支的**手动挂钩**（在内核源码里手工加调用点），因为运行时挂钩机制在这类内核里常未开启或工作不正常；若坚持用 `main` 分支，则要求内核配置里打开 `CONFIG_KPROBES=y` 与 `CONFIG_EXT4_FS=y`。
4. **配置与编译**：`CONFIG_KSU=y` 编进内核。若还想用可加载内核补丁模块（KPM），文档注明低于 4.19 的内核需要从 4.19 反向移植 `set_memory.h`，且非通用内核规范设备要额外打开 `CONFIG_KALLSYMS=y`、`CONFIG_KALLSYMS_ALL=y`。
5. **打包并刷入 boot 镜像**：联发科平台还要处理镜像校验（AVB / vbmeta），处理不当可能造成无法开机、连恢复模式都进不去。
6. **安装管理器应用并验证**：装对应版本的管理器，确认能识别到 root；版本与签名不匹配会识别失败。

### 3.3 现实里最难的一环：解锁

2026 年小米/红米的解锁已经不是跑一条命令的事。多个来源一致提到的限制：

- 需要在小米社区应用里申请解锁资格，有账号等级、答题或审核、每日名额等门槛；国行设备与国行账号限制更严。
- 绑定账号后通常还要等待约 168 小时（7 天）；单个账号有年度设备数量上限。
- **解锁会清空手机全部数据**，且会影响官方保修、部分安全功能与后续系统更新。
- 具体门槛随地区、系统版本、账号状态变化，各家资料给的数字不完全一致；**以小米社区应用里实际显示的为准**，不要照搬网上教程里的固定天数。

## 四、如果只是想 root 这台手机，更实际的选择

| 方案 | 做什么 | 代价 / 前提 |
| --- | --- | --- |
| **Magisk**（推荐给「只想要 root」） | 提取官方 boot 镜像，用应用修补后刷回去，不要求内核是 5.10+ | 仍需解锁 Bootloader 并清空数据；对 4.14 非通用内核规范设备支持成熟，XDA 上这台机型有实际成功案例 |
| **APatch / KernelPatch** | 同样是修补 boot 镜像，但走内核补丁路线；SukiSU 的 KPM 也源于此 | 需内核开启 `CONFIG_KALLSYMS` / `CONFIG_KALLSYMS_ALL`，这台机器是否默认开启**未核实**，要自己查；社区资料显示 4.14 内核可用，但不是零门槛 |
| **第三方系统的内核 + Magisk** | 刷 LineageOS 等社区系统，再用 Magisk 修补其 boot 镜像 | 要换系统，数据全清，且第三方系统本身可能有相机、指纹等小毛病 |
| **SukiSU-Ultra 自行编译内核** | 按第三节走完整流程 | 门槛最高：需要内核编译、调试、救砖能力；但能拿到这个项目的隐藏检测、KPM、主题生态等特性 |

## 五、风险和边界（动手前必须知道）

- **数据**：解锁必然清空全部数据，先完整备份照片、聊天记录、账号凭证。
- **变砖**：联发科平台加上镜像校验，刷错或校验处理不当可能无法开机、甚至进不了恢复模式，需要线刷救砖；救砖也依赖官方固件和工具可用。
- **保修与更新**：解锁与 root 通常影响保修，并可能让官方系统更新推送失效。
- **应用检测**：银行、支付、部分游戏与企业应用会检测 root 状态；本项目自带隐藏机制，但隐藏不是保证，且需要额外配置。
- **这台机器本身较老**：2021 年机型，社区活跃度与最新系统适配都在衰减，遇到问题能找到的现成答案比新机型少。
- **本次没有动过任何手机**：这是一份纸面调研，没有连接设备、没有刷写、没有下载或编译任何固件。

## 六、给结论排个优先级

1. **先确认型号和当前系统版本**（设置里看型号与内核版本）。如果内核是 4.14 系，本结论成立；若是别的机型或已经刷了 5.10+ 内核的第三方系统，需要重新评估。
2. **确认 Bootloader 能不能解锁**，这是所有方案共同的前置条件；不能解锁，后面全部免谈。
3. **只想要 root → 用 Magisk**；**想体验 SukiSU 特性 → 准备编译内核**，建议先用备用机练手，并保留原厂 boot 镜像以便回退。

## 七、术语解释

| 名词 | 含义 |
| --- | --- |
| root | 安卓上的超级用户权限，可以改动系统级文件与行为 |
| 内核 | 系统最底层、直接管理硬件的程序；这里的 4.14 / 5.10 是它的版本号 |
| 通用内核规范（GKI） | 谷歌从 Android 12 起要求新机采用的内核形态；5.10 以上且符合规范的设备可以只替换一个内核模块就获得 root |
| boot 镜像 | 开机时加载内核和初始系统的那一小块镜像，root 方案通常改它 |
| 内核模块（LKM） | 可以在运行时加载进内核的一小段代码，不用重编整个内核 |
| Bootloader | 开机第一段程序，负责校验系统签名；锁着时不接受改动过的镜像 |
| 镜像校验（AVB / vbmeta） | 安卓的启动校验机制，改动 boot 后若未正确处理可能拒绝启动 |
| kprobe / 手动挂钩 | 内核里"在某个函数执行时插入自己的代码"的两种办法：前者运行时注册，后者要改内核源码 |
| KPM | 基于 KernelPatch 的内核补丁模块，可在运行时往内核里加载额外功能 |
| Magisk / APatch | 两个常见的安卓 root 方案，前者改 boot 里的初始系统，后者用内核补丁 |
