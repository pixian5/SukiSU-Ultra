## 一、交接文档的关键错误（重要）

文档 §7 称「simonpunk/susfs4ksu 的 tag 1.4.2-kernel-4.14 提供 SukiSU 需要的全部符号」——**不成立**。
`SukiSU-Ultra@builtin(1cfa573)` 引用的是 **SukiSU 扩展版 susfs UAPI**（仅存在于
ShirkNeko/susfs4ksu 的 `gki-android14-6.1` 等 GKI 分支，v2.3.0；其 `kernel-4.14` 分支与
simonpunk 1.4.2 完全一致，**没有**扩展）。缺失符号包括：
`SUSFS_MAGIC`、`susfs_add_sus_path_loop`、`susfs_start_sdcard_monitor_fn`、
`susfs_parse_priority_app_strings`、`susfs_set_priority_uid_filter`、
`susfs_set_avc_log_spoofing`、`susfs_get_enabled_features`、`susfs_show_variant/show_version`、
`susfs_set_cmdline_or_bootconfig`、`susfs_add_open_redirect`、`susfs_add_sus_map`、
`susfs_set_hide_sus_mnts_for_non_su_procs`、CMD_SUSFS_* 新命令集，以及
`susfs_extra_works`、`susfs_add_sus_avd_allowed_by_type`。
且 SukiSU 侧所有调用签名都是 `void fn(void __user **)`，UAPI 结构体带 `err`/`flags`，
与 vanilla 1.4.2 的 `int fn(struct st_* __user)` 二进制布局**不兼容**。

## 二、实际采用的方案（4.14 兼容层）

保留 vanilla susfs-1.4.2-kernel-4.14 的内核机制（已验证可编译：本内核的
inode/super_block/task_struct/user_struct/mnt 都有 `android_kabi_reserved*` 字段），
在其上补齐 SukiSU 扩展 UAPI：

1. `include/linux/susfs_def.h`：整体换成 ShirkNeko GKI 分支版本（SUSFS_MAGIC、全套
   CMD 码、TIF_PROC_* 33-35 位 inlines——arm64 thread_info.flags 为 u64，24 位以上空闲）。
2. `include/linux/susfs.h`：保留 vanilla 内部结构体，新增 SukiSU UAPI 结构体
   （命名冲突的加 `_v2` 后缀；KSTAT_SPOOF_* 12 个细粒度标志）+ 全部新函数声明。
3. `fs/susfs.c`：
   - `susfs_add_sus_path`/`_loop`：GKI 签名，内核侧 `kern_path` 自行解析 ino（loop 无
     周期重挂机制，退化为普通 add）。
   - `susfs_add_sus_kstat`：GKI flags 语义——未置位字段用 `vfs_getattr` 取真实值填充，
     再复用 vanilla 全字段 spoof 机制；`SPOOF_DEV` 时才做 `old_decode_dev`。
   - `susfs_update_sus_kstat`：GKI 结构体，按 SIZE/BLOCKS 标志更新，未找到返回 -ENOENT。
   - `susfs_set_uname`/`susfs_enable_log`：薄包装（支持 "default" 复位语义）。
   - `susfs_get_enabled_features`（真实汇报编译特性）、`susfs_show_version`（"1.4.2"）、
     `susfs_show_variant`（"NON-GKI"）。
   - `susfs_add_sus_avd_allowed_by_type`/`susfs_spoof_avd_allowed_rcu`：按 GKI 原样移植
     （hash_32 + DEFINE_HASHTABLE(18) + mutex），供 SukiSU selinux/sepolicy.c 记录
     被注入 allow 规则前的原值（本 4.14 树无 avc 查询 hook，spoof 侧暂无调用方）。
   - `susfs_extra_works`：定义 + INIT_WORK（runner 为空操作，setresuid hook 需要该符号）。
   - **Stub（消费参数、err=0、pr_warn_once）**：`set_cmdline_or_bootconfig`、
     `add_open_redirect`、`add_sus_map`、`set_avc_log_spoofing`、
     `set_priority_uid_filter`、`parse_priority_app_strings`、
     `start_sdcard_monitor_fn`（这些功能在 4.14 无内核 hook 支撑）。
   - `set_hide_sus_mnts_for_non_su_procs`：存标志位即可（SukiSU 语义下山挂载隐藏由
     SukiSU 自己的 umount provider 处理，vanilla sus_mount 链表本就为空）。

对隐藏检测的影响：Momo 检测的核心面（sus_path、sus_kstat、spoof_uname、隐藏
ksu/susfs 符号、avd 规则还原）均为真实实现；stub 的功能（open_redirect、sus_map、
cmdline 伪装、avc 日志过滤、priority uid 过滤、sdcard 监控）属于增强项，不影响主线。

## 三、构建环境坑（按出现顺序）

1. `android.googlesource.com` 偶发 SSL 中断 → `curl -C - --retry 5 --retry-all-errors` 重试续传。
2. 必须 `apt install binutils-aarch64-linux-gnu bc`（4.14 内核用 `-no-integrated-as`，
   clang 外部汇编器走 `aarch64-linux-gnu-as`；bc 用于生成 timeconst.h）。
3. `CONFIG_MILLET=y` 引用树外 vendor 模块（`/workspace/vendor/xiaomi/kernel_modules`），
   历史成功构建均为 `# CONFIG_MILLET is not set`——直接关掉，不要找仓库。
4. 其余历史关键配置：`CONFIG_KALLSYMS_ALL=y`、`CONFIG_KPROBES=y`、
   `# CONFIG_KPROBES_SANITY_TEST is not set`、`CONFIG_FRAME_WARN=0`（见
   `tools/camellian/config/key-config-options.txt`；其中 LTO 两行已被
   `lto-cfi-config-options.txt` 取代，defconfig 自带正确值）。
5. `susfs.c` 1.4.2 无条件 `#include "../drivers/kernelsu/core_hook.h"`，SukiSU 树无此文件；
   且 sus_su 相关 include 需包在 `#ifdef CONFIG_KSU_SUSFS_SUS_SU` 内（本配置未启用 sus_su）。
6. SukiSU `sulog/event.c:143` 上游笔误调 `strncpy_from_user_nofault`，4.14 没有；
   改为同文件其他处使用的 `ksu_strncpy_from_user_nofault`（kernel_compat.h 提供）。
7. DTS：`camellian.dts` 的 `#include <camellian/cust.dtsi>` 尖括号找不到
   `arch/arm64/boot/dts/mediatek/camellian/cust.dtsi`，改引号 `"camellian/cust.dtsi"`；
   cust.dtsi 来自 `tools/camellian/patches/cust.dtsi`。
8. preinit runner 需要 `$(objtree)/usr/include/linux/unistd.h`：全新 O= 树第一次构建
   会提示 `preinit disabled`——先 `make O=... headers_install` 再全量重编即可编入。
9. `systracker_platform.o` 并行构建偶发 `.tmp` 竞争（同一目标被 CC 两次）——重跑即过。
10. ROM 5.8GB 全量下载后 `tar -xzf rom.tgz camellian.../images/boot.img` 单文件解包即可，
    MD5 须等于 `f8e4f42a4538b03c519bb70921d88bcc`。

## 五、遗留与后续

- 刷机路径不变：`vbmeta-verification-disabled.img` 已在桶里；fastboot 刷 boot 分区。
- 若后续要补 stub 功能，优先级建议：cmdline/bootconfig 伪装（hook fs/proc/cmdline.c）>
  open_redirect（hook fs/open.c，1.3.8 曾有 sus_path 变体可参考）> sus_map（proc maps hook）。
- sus_path_loop 目前是普通 add 语义：路径被删重建后需重新下发（SukiSU manager 的
  sdcard_monitor 流程在本 4.14 上不工作，属已知限制）。
- 构建产物树保留在构建机：`/workspace/camellian-kernel`（含全部改动，未提交 git）、
  `/workspace/SukiSU-Ultra`、`/workspace/out`、`/workspace/dist/`。
  下次迭代直接增量 `make` 即可（约 10 分钟）。
