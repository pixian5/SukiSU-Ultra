## P0：复现闭环（最优先）

1. **从新补丁重建一次内核**
   - 在云电脑按 `tools/camellian/` 流程执行，确认 `integrate.py` 第 8、9 步生效。
   - 产物与 `final3` 对比：`Image.gz-dtb`、`vmlinux`、最终 boot 镜像的校验值。
   - 验收：要么字节一致；要么差异仅来自时间戳/构建号，并给出「功能等价」证据（符号存在、日志关键字、真机授权可选）。
   - 风险提示：重建与刷机是两件事，重建本身不碰手机。

2. **回传云电脑实际修改文件**
   - 若云电脑实例仍在：导出 `kernel/reboot.c`、`kernel/supercall/dispatch.c` 的实际 diff，与仓库补丁逐行比对。
   - 验收：两边 diff 一致，或差异已解释并记录。

3. **更新 `MANIFEST` 的最终结论**
   - 重建完成后补记新的构建号、镜像校验值与「是否等价」结论。

## P1：资产安全与仓库同步

4. **异地备份**
   - 至少复制：`boot_b-before.img`、`final3` 镜像、管理器 APK。
   - 目标：对象存储或另一台机器，保留校验清单。
   - 验收：从异地副本重新计算 MD5/SHA256 与清单一致。

5. **合并上游 7 个提交**
   - `git fetch upstream && git merge upstream/main`。
   - 冲突大概率只在 `docs/README.md`、`docs/zh/README.md` 的索引段落。
   - 验收：合并后本地构建脚本不变，文档索引两条都在。

6. **补齐/校验文档约定**（本轮已完成大部分）
   - 根 `README.md`、`文档索引.md`、`经验/`、进度与下一步文档。
   - 后续每轮按规则更新。

## P2：真机收尾（需要用户在场）

7. **重启一次**
   - 让 Zygisk Next 真正生效；重启前确认回退件仍在。

8. **逐个启用模块**
   - 当前 16 个模块多数 disabled，一次只开 1–2 个，重启验证后再继续。
   - 验收：每次重启后管理器仍显示「工作中」，授权正常。

9. **核对超级用户列表**
   - 撤销不需要的授权；记录当前可用配置（模块清单、授权清单、镜像校验值）。

10. **Magisk 残留评估（可选）**
    - `/data/adb/magisk`、`magisk.db`、`post-fs-data.d`、`service.d` 仍在。
    - 清理前必须备份；不确定就不动。

## P3：可选优化（需用户拍板）

11. **KPM / SuSFS 可行性再评估**
    - 现状：KPM 缺 KernelPatch 钩子，SuSFS 需外部内核补丁，均属结构性不可用。
    - 如要推进，等于引入新的外部补丁链，工作量和风险都显著上升。

12. **管理器「隐藏应用」规避**
    - 该功能会禁用自身启动入口，恢复只能靠电脑覆盖重装。
    - 建议保持关闭。

## 不要做

- 不要再刷调试版内核（`allow_shell=true`，任何能连 adb 的人都能 root）。
- 不要在管理器里开「隐藏应用」。
- 不要在未明确授权时写手机任何分区、重启、切槽或装应用。
- 不要把「编译通过 / 开关打开」当成「功能可用」。
