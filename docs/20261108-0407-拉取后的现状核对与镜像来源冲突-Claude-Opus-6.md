**具体后果**：如果现在按「从对象存储取最新镜像」的流程刷机，刷进去的会是这份没有出处说明的 `v2.3.0` 内核，而不是发布说明里那份 `1.4.2`。两份镜像都**没有在真机上验证过**，刷错版本后排查会非常困难。

两份镜像的启动结构我都按原厂布局重新校验过：大小 64 MiB、启动头版本 2、内核是纯 gzip、原厂内存盘 / 设备树 / 校验区段逐字节与原厂一致、安卓校验尾部已正确重定位、填充区全零，**8 项全通过**。也就是说两份都「结构合格、能写进启动分区」，但「结构合格」不等于「开机正常」，更不等于「隐藏有效」。

## 三、对照上一轮修改建议：哪些做了，哪些没做

那份 03:35 的建议是针对 v0.0.4 写的，另一台云电脑换了技术路线，所以不能简单说「没执行」，但每一条的**最终状态**如下：

| 建议项 | 现状 | 判定 |
| --- | --- | --- |
| `sus_map` / `avc_log_spoofing` / `priority_uid_filter` 要标成「不支持」 | 新方案里这几条仍是空壳函数：吃掉参数、返回成功、只打一次内核警告；发布说明和编译记录里如实写了「已注册但不产生隐藏效果」 | **部分落实**：文档诚实了，但管理器界面依然会当成「成功/支持」，用户仍可能被误导 |
| `sus_path_loop` 不要静默降级 | 明确写「无周期重挂，等同一次性添加」 | 文档落实，功能仍降级 |
| `CONFIG_KALLSYMS_ALL` 的取舍 | 从内核里提取的实际编译配置显示，两份镜像**都还是 `=y`**（会把全部内核符号暴露给有 root 的进程，本身是可被检测的特征） | **未处理**，也没有在仓库说明里写清这是取舍 |
| `CONFIG_MIHW` 的取舍 | 发布说明写「MIHW 关闭，小米 millet 模块不在开源树」，但发布包内核实际是 **`MIHW=y`、`MILLET=n`**；对象存储那份才是 `MIHW=n` | **说明与镜像对不上**，属表述错误 |
| 版本号统一 | `tools/camellian-susfs/VERSION` 是 `0.0.5`，标签是 `v0.0.5`，现在对上了 | 已一致（但工具包说明文件仍整篇描述旧的 2.3.0 方案，文档漂移） |
| 更新工具包说明里的「已知限制」 | 未改；`tools/camellian-susfs/README.md` 的能力表仍是 v0.0.4 的 | 未做，改用发布说明承载 |
| 给出真机验证清单 | 发布说明有 5 条判据，但**缺「不要用 `adb shell su` 判断成败」**，也没有超过 3 分钟无反应视为失败的时限 | 不完整 |
| 复现闭环 | **最严重**：3 个新提交全是文档，兼容层的全部源码改动只留在那台构建机的 `/workspace/camellian-kernel`（记录里明确写「未提交 git」）。发布说明的「复现」只有一行打包命令，根本无法重建内核 | **未闭环** |

另外，授权链路的两处关键修复（重启系统调用里给后台程序传递内核通道、读取应用配置时返回默认档而不是报错）在仓库现有的两份集成补丁里**都在**：`camellian-integration.patch` 第 793 行起有重启钩子，`sukisu-integration.patch` 第 282 行起有默认档回退。新镜像按交接文档使用了这批补丁，因此**源码层面**没有丢修复；但因为源码改动没入库，这一点无法从仓库复现，也无法在真机开机前百分之百确认。

## 五、给下一步的建议（按优先级）

1. **先定「唯一可信的那份镜像」**：以 GitHub 发布页 `camellian-susfs-v0.0.5` 的资产为准（校验值已在本机核对一致）。对象存储那个同名对象应改名归档或补一份校验清单，并告知所有并行工作的云电脑**不要再往这个对象名写文件**。否则任何人按「取最新」拿到的都是来路不明的那份。
2. **让另一台云电脑把兼容层源码提交进仓库**：至少提交内核侧三个文件的改动（接口定义头、内部结构体头、`fs/susfs.c`）和它遇到的源码修正，形成可复现补丁。没有源码，这一版就只是一个无法审计、无法再改的二进制。
3. **两条技术路线不要并行刷**：`1.4.2 + 兼容层` 与 `2.3.0 接口翻译层` 是不同实现，先选一条做真机验证，别用一份的经验去推断另一份。
4. **真机验证仍待授权**：能开机、管理器「工作中」、后台有 root 子进程、内核日志出现 `susfs is initialized! version: 1.4.2`、管理器能读到特性列表、再用 Momo 复测；**不要用 `adb shell su` 判断成败**（调试模式关闭时它本来就不能提权）。任何写手机的动作都需要用户明确说「刷机」。
5. **GitCode 镜像补齐**：落后 3 个提交、缺 v0.0.4 与 v0.0.5 发布资产。用户此前明确要求过「GitCode 也要上传 Release」，这一项尚未完成。
6. **文档小修**：更正发布说明里「MIHW 关闭」的表述；把工具包说明的能力表更新成当前路线；在交接文档第 6 节补上「1.4.2 也不含扩展接口，需自建兼容层」。
