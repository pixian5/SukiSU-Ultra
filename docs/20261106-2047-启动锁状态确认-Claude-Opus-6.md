# 启动锁状态确认（红米 Note 10 5G 实机）

> 核对时间：2026-11-06 20:43–20:47（GMT+8）
> 撰写模型：Claude Opus 6
> 触发：用户明确同意「先做第四项把底摸清」，即让手机进入刷机模式读一次底层启动锁变量
> 工具：`~/Library/Android/sdk/platform-tools/` 下的 `adb` 与 `fastboot`
> 前置文档：[实机核对报告](./20261106-2037-红米Note10-5G实测核对-Claude-Opus-6.md)、[纸面兼容性评估](./20261106-2030-红米Note10-5G兼容性评估-Claude-Opus-6.md)

## 一、结论

**启动锁确实已经解开。** 刷机模式（开机第一段程序所在的层级，最权威）明确返回 `unlocked: yes`、`secure: no`。此前系统里显示的「启动锁锁定 / 官方校验通过 / 未解锁」全是**被改写过的显示值**，用来让应用以为这是台原封未动的机器——这与 Magisk 已在提权的现象完全对上了。

这个结果把上一份实机报告里唯一悬着的问题解决了，也**大幅降低了「换成 SukiSU-Ultra」这条路的前置门槛**：解锁、等待审核、因解锁清空数据这三件事都不用再做了。剩下的障碍集中在内核本身（见第四节）。

## 二、执行了什么，没执行什么

### 2.1 执行了的动作（按顺序）

| 步骤 | 命令 | 目的 |
| --- | --- | --- |
| 1 | `adb devices -l` + 读 `ro.product.model` | 确认仍是同一台 `M2103K19C` |
| 2 | `adb reboot bootloader` | 重启进刷机模式（**这一步会重启手机，已获用户同意**） |
| 3 | `fastboot devices` | 确认设备已在刷机模式枚举 |
| 4 | `fastboot getvar unlocked` | 读解锁标志 |
| 5 | `fastboot getvar all` 并筛选相关字段 | 交叉验证 |
| 6 | `fastboot getvar secure / is-userspace / current-slot / product` | 单项复核 |
| 7 | `fastboot reboot` | **重启回正常系统** |
| 8 | `adb wait-for-device`、等开机完成标志 | 确认恢复 |
| 9 | `adb kill-server` 并复查进程 | 清理本轮调试服务 |

### 2.2 明确没有执行的动作

**没有**执行任何解锁、擦除、刷入、改分区、改属性、装卸载应用的命令。特别是没有碰 `fastboot flashing unlock`、`fastboot oem unlock`、`fastboot erase`、`fastboot flash` 这一类会改变设备状态的命令。全程只有两次重启和若干只读查询。

### 2.3 两个读不到的命令（不影响结论）

- `fastboot getvar unlocked_by_user`：返回变量不存在。
- `fastboot oem device-info`：返回未知命令。

这是联发科平台常见情况；`fastboot getvar all` 里已经给出了同样的解锁标志，结论不依赖这两条命令。

## 三、原始读数

```
$ fastboot devices
pvwwjztokvvs8llb	 fastboot

$ fastboot getvar unlocked
unlocked: yes

$ fastboot getvar all | grep -i -E 'unlocked|secure|tamper|verified|is-userspace|current-slot|slot-count|version-bootloader|product:'
(bootloader) unlocked: yes
(bootloader) secure: no
(bootloader) product: camellia
(bootloader) is-userspace: no
(bootloader) slot-count: 2
(bootloader) current-slot: b
(bootloader) version-bootloader: camellia-8a9d4ca27-20230426150734-20230

$ fastboot getvar secure
secure: no
```

怎么读这些值：

| 值 | 含义 |
| --- | --- |
| `unlocked: yes` | 启动锁已解开，允许刷入未由厂商签名的镜像 |
| `secure: no` | 启动时的安全校验不处于锁定强制状态 |
| `is-userspace: no` | 读的是**开机引导层**的变量，不是系统里那层可以被改写的属性，所以这个结果最可信 |
| `product: camellia` | 与系统里读到的机型代号一致，确认没连错设备 |
| `current-slot: b` / `slot-count: 2` | 双槽位，当前从第二份系统启动 |

对照上一份实机报告里系统层读到的 `ro.boot.flash.locked=1`、`ro.boot.vbmeta.device_state=locked`、`ro.boot.verifiedbootstate=green`、`sys.oem_unlock_allowed=0`：两者相反，可以确定那些属性是被 root 隐藏类模块改写过的。`sys.oem_unlock_allowed=0` 只表示开发者选项里的开关没打开，与真实的解锁状态无关。

## 四、对「换成 SukiSU-Ultra」这条路意味着什么

| 环节 | 之前（纸面评估） | 现在（两次实机核对后） |
| --- | --- | --- |
| 解锁 Bootloader | 以为要办：社区申请、等级/审核、约 7 天等待、清空数据 | **已完成，不用再做** |
| 是否已有 root | 以为没有 | 已有 Magisk Alpha，可正常提权 |
| 内核版本 | 4.14，非通用内核规范 | 实测确认，无现成安装包可用 |
| 挂钩方式 | 推测可能要手动 | **确认必须手动**：运行时挂钩开关未开启 |
| 内核符号全量表 | 未评估 | **未开启**，另一类修补启动镜像方案的前提也不满足 |
| 现有 root 方案 | 未考虑 | 需要先移除 Magisk，两者会争抢同一处启动镜像 |
| 启动校验 | 以为要处理 | `vbmeta` 系列分区仍在，改 boot 后仍需处理；但解锁状态下不再需要绕过厂商签名 |

**换句话说**：解锁这个最大的现实门槛已经不存在了，剩下的纯粹是「内核编译」这一件技术活——取这份 `V14.0.4.0.TKSEUXM` 固件对应的内核源码，先独立编出能开机的内核，再按项目的 `builtin` 分支手动加挂钩、打开所需配置，编出完整内核/boot 镜像，处理启动校验后刷入，并先移除现有 Magisk。

风险仍在：内核编译与救砖能力是硬要求，刷错可能开不了机，动手前必须备份数据并保留原始 boot 镜像以便回退。这次确认**不等于**建议现在就动手，用户明确说的是「先摸清底，再决定要不要走」。

## 五、恢复与清理（可核对）

- `fastboot reboot` 返回 `Rebooting OKAY`。
- 等待开机完成后复查：`sys.boot_completed=1`、型号仍是 `M2103K19C`、`magiskd` 守护进程照常以 root 运行（说明 root 方案开机自启未受影响）。
- `adb kill-server` 之后 `pgrep -fl adb` 无残留进程；仓库工作区除本地助手记录 `.workbuddy/` 外没有新增临时文件。
- **手机现在处于正常系统、可正常使用**，没有停在刷机模式。

## 六、术语说明

| 名词 | 含义 |
| --- | --- |
| 刷机模式 / fastboot | 关机状态下进入的、由开机引导层提供的接口，供电脑读取变量和刷写分区 |
| 开机引导层 | 比安卓系统更早运行、负责校验并加载系统的那一层，这里的读数不易被系统内的工具改写 |
| `getvar` | 刷机模式下读取变量的只读命令 |
| 启动锁 / 解锁 | 引导层是否接受未经厂商签名的镜像；解锁后才能刷改过的内核或启动镜像 |
| 安全校验标志（secure） | 引导层是否处于强制校验状态 |
| 槽位 | A/B 双份系统交替升级的设计，当前从哪一份启动 |
| 隐藏类模块 | root 之后用来改写系统属性值、让应用误以为设备未改动的工具 |
| 启动镜像 / boot 分区 | 开机时加载内核与初始系统的存储区域，两套 root 方案都会改它 |

## 七、复核命令

```sh
ADB="$HOME/Library/Android/sdk/platform-tools/adb"
FASTBOOT="$HOME/Library/Android/sdk/platform-tools/fastboot"

"$ADB" devices -l
"$ADB" reboot bootloader          # 会重启手机
"$FASTBOOT" getvar unlocked
"$FASTBOOT" getvar all 2>&1 | grep -i -E 'unlocked|secure|is-userspace|product:'
"$FASTBOOT" reboot                # 回到正常系统
"$ADB" wait-for-device
"$ADB" kill-server
```
