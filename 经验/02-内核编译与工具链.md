# 内核编译与工具链

## 环境

- 厂商内核源码：`MiCode/Xiaomi_Kernel_OpenSource`，分支 `camellian-t-oss`，提交 `f4e416aea06c81f1e661d0524c0554f0538d11cb`。
- 云电脑 Ubuntu 24.04、大小写敏感文件系统；本机 Mac 编不了这颗内核。
- 编译器：AOSP prebuilt `clang-r383902`（clang 11.0.1，android11-release）。

## 最容易踩的配置坑

- **`CC=clang` 必须作为 make 变量传入**，不能只 export 到环境变量。只放环境变量时，内核 Makefile 的 `check-clang-specific-options` 会静默删除 `LTO_CLANG`、`CFI_CLANG` 等 clang 专属选项并重算配置，之后改回 clang 也不会自动补回。
- 编译后必须把最终 `.config` 与出厂 `ikconfig` 对照，确认 `THIN_ARCHIVES / LTO / THINLTO / LTO_CLANG / CFI / CFI_CLANG / CFI_CLANG_SHADOW` 都是 `y`。
- 早前「defconfig 漏抄父开关」的说法是错的，已被更正；不要照旧文档复跑。

## 4.14 兼容适配

- `static_call` 是 5.10 以后机制，4.14 需跳过相关头文件。
- 4.14 有 `kvzalloc` 但没有 `kvcalloc`，可用 `kvzalloc(n * size, flags)` 等价替代。
- 4.14 arm64 没有 vDSO 时钟模式、`elf_hwcap2` 等机制，CPU 伪装只能做真实存在的三项（`reg_midr`、`loops_per_jiffy`、`elf_hwcap`）。
- 开机早期 preinit runner 需要先 `make headers_install`，并修 nolibc 的 `clone3`、`linux/mount.h`、`ksys_close`、`__kernel_timespec` 四处。

## 构建与验证

- 产物：`Image.gz`、`Image.gz-dtb`、`vmlinux`；LTO 全量构建耗时长，先给阶段性结论再收尾。
- `drivers/media/platform/mtk-vcu/Makefile` 里 `mtk_vcodec_mem.o` 重复出现，在 thin archives + LTO 下会报重复符号，必须删掉多余条目。
- 构建后核对符号：`ksu-prefixed symbols` 数量、`ksu_preinit_runner` 区间、KPM/SuSFS 开关是否真的编译进去。
- 手动挂钩构建用 `builtin` 分支；`main` 分支是 kprobe 运行时注册，两者不能混用。
- **做「换一份实现能不能编过」的验证时，务必自动备份并恢复内核树**：`tools/camellian-susfs/scripts/verify-public-uapi.sh` 会在退出时还原 `fs/susfs.c`、`fs/susfs_abi.c`、两个头文件与 `fs/Makefile`，失败也不污染后续构建。脚本参数化源码目录/构建目录/工具链/参考文件目录，可整包迁移到任意 Linux 编译服务器；**不要在 macOS 本机跑**（工具链是 x86_64 Linux 二进制）。
- 换实现之前先做静态预判：扫一遍参考源码里「调用了但本文件没定义」的 `ksu_*` / `susfs_*` 符号，通常就是链接阶段会报的缺符号，能提前判断要不要补钩子补丁。
- 云电脑长时间停在 `starting` / `failed` 时，先查平台快照是否完整（文件数、字节数），再尝试唤醒或升级；文件安全靠快照，不要靠「应该没丢」。备用服务器要先探测 SSH 端口与用户，连不上就换路径，别在连接上反复耗时间。
- **静态扫「缺符号」不能只靠一种正则**：带 `__attribute__((hot))` 的函数、结构体指针返回值、头文件里的 `static inline`、以及被注释掉的函数名，都会让「调用了但没定义」的判断出错。写进结论前要逐行核对定义与调用，最好再用单文件编译验证一次。本仓库就因此把「缺 7 个符号」误写成结论，后来更正为只缺 2 个。
- 验证换实现时用**两段式编译**：先单独编译目标 `.o`（几秒），再跑全量；并把并发数做成可调（小内存机器上 `-j4` 会卡在依赖扫描，`-j2` 更稳）。全量卡住至少还有第一段的结论可用。
