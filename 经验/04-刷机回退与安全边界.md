# 刷机回退与安全边界

## 授权边界

- 用户原话：「在我明确说刷机之前，你不要修改我手机的数据。你可以只读」。
- 允许：读系统属性、只读文件、进程与挂载、已有文件；设备本来就处于刷机模式时读变量。
- 禁止：刷/擦分区、切槽、写校验分区、重启（含为读变量而重启进刷机模式）、推文件、装应用、跑官方刷机脚本。
- 「继续」「下一步」这类含糊指令**不算授权**；必须是明确说「刷机」或点名某个写操作。

## 刷写策略

- 只写当前槽 `boot_b`，保留 `boot_a`。
- 绝对不能用 `flash_all_lock.sh`：会重新锁启动锁，自编内核无法启动。
- 刷写前确认：镜像来源、校验值、当前槽位、精确回退件、电量与 USB 稳定性。

## 回退顺序

1. 同槽刷回精确复原件 `boot_b-before.img`（当前槽原状，含 Magisk）；
2. 同代干净原厂镜像 `boot-stock.img`（会失去 root）；
3. 官方全量恢复（写两个槽，风险与影响面最大）。
- **第一优先不是切槽**；切槽是另一种状态切换，不是回退。

## 成功判据（重要）

- **不要用 `adb shell su` 判断成败**：调试模式关闭时 shell 本来就不能提权，这是安全设计。
- 正确判据：管理器显示「工作中」+ 进程列表有 `com.sukisu.ultra:root:0` + 内核日志 `is_manager: 1`。
- 调试版内核 `allow_shell=true`，任何能连 adb 的人都能 root，验证完必须换回关闭调试的版本。

## 管理器操作禁忌

- 不要开「隐藏应用」：会禁用管理器自身 launcher activity，入口消失后只能靠电脑 `adb install -r` 覆盖重装恢复。
- 不要一次启用全部模块：一次 1–2 个，重启验证后再继续。
