# 设备与固件版本

## 设备身份

- 本机设备型号 `M2103K19C`（`camellia`，红米 Note 10 5G 国行 C 版硬件）。
- 硬件是国行 C 版，但系统固件走 **EEA 分支**：`ro.miui.build.region=eea`，版本 `V14.0.4.0.TKSEUXM`，运行时区域 `ro.miui.region=US`。
- **刷机与回退必须按固件版本分支匹配，不能因为硬件是 C 版就刷国行包。**

## 槽位与 VAB

- 设备是虚拟 A/B（VAB），当前系统槽 `b`，`boot_a` 一个字节都没动过。
- 试刷自定义内核只写当前槽（`boot_b`）；官方全量恢复脚本会写两个槽，那是另一场景，别混。
- 分区设备号（如 `sdc30`/`sdc49`）可能随重启变化，读写前以当前 `by-name` 与内核报告的大小为准。

## 启动镜像代际

- 同一内核版本串 **不等于** 同一份镜像。`V14.0.4.0` 与 `V14.0.6.0` 都显示 `4.14.186-perf-gf8d872e9279c`，但构建者标识、编译时间、内核/内存盘大小、MD5 全不同。
- 判断代际要比较：完整版本行（含构建者 + 编译时间）、内核大小、内存盘大小、校验值；**不能只看文件名或内存盘大小**。
- 当前槽 `b` 的精确复原件只有 `backup/camellian/boot_b-before.img`（MD5 `531c534bcc8d3172e03b12a2f6dd135d`）。
- 用户提供的 `redminote10boot.img` / `magisk_patched-28103_liPdl.img` 属于另一槽那一代（内核 `ga368196f0bd0`，2023-03-10），**不能当当前槽回退件**。
- `V14.0.6.0` 的 3.87 GB 原包与提取件已按用户要求删除，只保留校验值；它不是当前系统的同版本回退件。

## 升级路线

- 从厂商 4.14 换到主线 Linux 7.x 不是「升级」，而是重做整套安卓/驱动/引导链移植，会失去电话、相机、数据等能力。
- 4.14 上游已于 2024-01 停止维护，厂商分支无安全补丁，这是设备固有风险。
